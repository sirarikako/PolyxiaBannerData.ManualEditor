# Codex Review 检查清单

用于每次 DSH 开发或返工后的独立审查。规则以 [AGENTS.md](../AGENTS.md) 为准，执行步骤见 [协作流程](agent-workflow.md)，云端契约见 [CI、构建与发布](ci-build-release.md)。本清单不代表已经完成验证；逐项记录“通过 / 不通过 / 未执行 / 不适用”，对后三种状态说明原因。

## 1. 调用前与 Git 基线

- [ ] 已阅读用户需求和适用的仓库规则，明确允许修改的范围、禁止事项、验收标准及平台要求。
- [ ] 已检查目录、分支、工作区、暂存区和未跟踪文件，并记录原有修改及基线；空仓库已注明无初始提交。
- [ ] 已使用本任务独立分支；未经用户明确授权没有在 `main` 上修改文件。
- [ ] 未覆盖、回退、暂存或提交用户已有修改，未自行 `stash`、破坏性清理或强制推送。
- [ ] DSH 输入方式来自已验证命令或本机帮助，工作目录正确，执行时限明确。
- [ ] 任务单包含行为要求、测试、范围和报告要求，没有凭据；DSH 不提交、不切分支、不推送、不创建或合并 PR。
- [ ] 已明确本地快速验证、云端构建和设备验收范围；实际 Flutter 版本与 `.fvmrc` 一致，缺失时没有假定已固定版本。

## 2. 调用状态和认证安全

- [ ] 已读取 DSH 的最终退出码及实际输出；没有把 0 退出码或自述“完成”当作验收通过。
- [ ] 运行中会话只跟踪同一进程，没有因等待返回而重复启动、提前审查或并发写入。
- [ ] 调用失败、超时、人工授权或无法确认进程结束时，已停止并报告；没有自动重试。
- [ ] 超时后仅处理明确属于本次调用的进程，没有批量终止其他 DSH 会话。
- [ ] 没有在仓库、提示词、日志或报告中泄露 API Key、完整认证配置或环境变量值。
- [ ] 若排除认证变量冲突，仅修改了 DSH 子进程环境副本；未修改父会话、用户级或系统级配置。
- [ ] 没有自动安装软件、要求 WSL / Docker，或引入无必要的调度器、数据库、服务、消息队列和第三方依赖。
- [ ] 没有擅自给 VM 安装 Android Studio、NDK 或模拟器；Android 使用真机 Wi-Fi ADB 或已有宿主机 Emulator，人工配对与授权未被绕过。

## 3. 实际 Git Diff 与实现

- [ ] 已阅读本轮实际差异及任务累计差异，没有仅检查文件清单或 Diff 统计。
- [ ] 已核对当前分支和 `HEAD`，检查相对起始提交的累计差异，没有遗漏已提交修改；DSH 意外提交或切分支时已停止并保留现场。
- [ ] 已覆盖暂存和未暂存改动、未跟踪新文件全文、删除文件、忽略规则及生成物；未把用户原有修改算作 DSH 交付。
- [ ] 没有越界修改、无关格式化、意外配置或锁文件变化；新增依赖和生成文件有明确必要性及授权。
- [ ] 实现覆盖需求和验收标准，关键逻辑结合上下文审查；业务实现主要由 DSH 完成。
- [ ] 已检查适用的边界与异常：空值、空输入、重复操作、无效或损坏输入、失败返回、资源释放及数据完整性。
- [ ] 已检查适用的回归风险：现有调用方、旧数据兼容、状态切换、异步或并发行为及平台差异。
- [ ] 没有硬编码测试答案、删除或禁用有效测试、弱化断言、跳过校验或隐藏失败。
- [ ] Codex 没有自行重写业务代码来绕过 DSH 返工。

## 4. 独立测试与平台验收

- [ ] 已按修改类型和风险选择相关自动化测试及仓库要求的检查，实际执行并读取结果。
- [ ] Codex 已独立执行关键验证；DSH 报告只用作线索，没有替代实际测试证据。
- [ ] 测试覆盖关键行为以及适用的边界、异常和回归场景，必要时补充独立验收或故障注入。
- [ ] 故障注入使用临时数据或隔离目录，未破坏真实数据；已检查并清理本次验证产生的副作用。
- [ ] Flutter 修改已按范围执行格式、静态检查和相关单元 / 组件 / 集成测试；必要完整构建优先交云端，不强制本地补齐大型 SDK。
- [ ] Windows 特有行为已有对应证据；不适用时说明原因。
- [ ] Android 特有行为已分别记录构建、模拟器和实机的实际验证状态；没有实机条件时明确“Android 实机测试未执行”。
- [ ] 没有把 Android 构建成功视为设备行为通过，也没有在必需平台验收缺失时宣告完整通过。
- [ ] 已分别记录代码验收、Android / Windows 云端构建和 Windows / Android 实机验收；模拟器结果未冒充实机结果。
- [ ] 纯文档修改已检查链接、规则一致性、修改范围、完整 Diff 和空白错误，没有运行无关业务实验。

## 5. 返工与停止判断

- [ ] 已记录 DSH 总调用次数及返工轮数：同一任务初次 1 次，本地 Review 与 CI 返工共享最多 3 轮，总调用尝试最多 4 次；失败尝试也计入。
- [ ] 每次返工都有具体问题、证据、影响、允许修复范围、执行时限及可执行验收条件。
- [ ] 每轮都有可比较的代码基线，并重新检查实际差异、问题专项验证及相关回归。
- [ ] 没有通过拆单、改名、换提示词或换会话重置预算，没有擅自放宽验收条件。
- [ ] CI 修复已注明失败 Run、受测提交、具体步骤及复验条件；修复后本地复验和新提交的 CI 均有证据，未在 PR 阶段重置预算。
- [ ] 调用故障、无法解决、条件缺失或第 3 轮复验仍失败时已停止，未发起第 4 轮返工。
- [ ] 只有满足全部必需验收项且无阻断问题才标记通过；否则报告部分完成或停止及具体原因。

## 6. GitHub CI、构建与发布（按任务范围适用）

- [ ] GitHub Actions 只运行检查、构建及已授权发布，没有运行 AI Agent 或接收 AI 凭据。
- [ ] `01-ci.yml` 遵守 PR / push main 的 format、analyze、test 契约，PR CI 使用最小只读权限，不默认执行完整双平台构建。
- [ ] `02-build.yml` 的手动 / 复用入口校验 Android、Windows 或 both 选择，独立 Job 使用对应 Runner；所选平台失败没有被隐藏。
- [ ] Flutter / Gradle 缓存有版本和平台边界，未缓存敏感数据；已记录磁盘占用和包体大小，Artifacts 按 7 天保留。
- [ ] 云端结果对应实际提交和 Run，所需 APK / 完整 Windows Release ZIP 可用；没有用旧提交或其他 Run 的产物替代。
- [ ] `03-release.yml` 仅按 `v*` Tag 发布；已验证 Tag 提交属于可信 `main` 历史且具有该提交的 CI 成功证据，再复用构建工作流；所需平台全部成功后才发布。
- [ ] Release 附件及 SHA256 对应同一提交和确切文件；只有发布 Job 有必要写权限，未自动合并 PR 或覆盖正式 V1、移动旧标签、替换既有正式 Release 附件。
- [ ] 公共 App 源码与原数据仓库分离；Private 数据、Token、签名密钥及 AI 凭据未进入源码、日志、缓存或产物，PR CI 不读取私有原数据。
- [ ] CI 失败已区分代码问题与基础设施故障；没有通过取消测试、弱化断言、放宽校验或反复重跑取得成功。

## 7. 最终报告与交付边界

- [ ] 报告包含：完成状态、DSH 调用次数和返工轮数、修改文件、Git Diff 审查结果、实际测试及结果、未解决问题、是否需要用户确认。
- [ ] 报告注明本地 / CI 返工来源、分层验收状态、实际云端 Run 和产物证据；待用户验收没有被代为确认。
- [ ] 未执行、受环境限制和未验证的平台环节已明确列出；没有重复使用历史实验结果冒充本次结果。
- [ ] 没有 DSH 调用的任务明确记录 0 次、0 轮。
- [ ] 提交、推送和创建 PR 均符合当前用户授权；未自动合并 PR。
- [ ] 仅本次云端方针文档整合适用：只改动四份规范文档；未创建或修改实际 Actions、`.fvmrc`、Flutter 代码、CastoriceWishBannerData 或 Schema，未安装 SDK、推送远端、创建 PR 或开展新的开发实验。
